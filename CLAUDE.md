# FlowSketch (repo name on GitHub: piper5ul/flowsketch; local dir ~/whimsy)

Whimsical-style diagramming app. Sharing (public read-only links, per-user invitations) and version history are server-side today; realtime is on the roadmap.

## Commands

- `npm run dev` — Vite on **5199** (not 5173) + Express on 3001 via `concurrently`
- `npm run check` — lint + typecheck + unit tests. Must be green before any commit (pre-commit hook runs it)
- `npm test` / `npm run test:watch` — Vitest (no DB needed)
- `npm run test:e2e` — Playwright; reuses a running dev server locally, starts its own in CI
- `npm run build` — `tsc -b && vite build`; `npm run build:server` compiles the API to `dist-server/`
- `docker compose up -d` — Postgres + MailDev for local dev
- Install with `npm install --legacy-peer-deps` (npm 10.9 arborist bug with vitest's peer set)

## Architecture (read this instead of re-reading the files)

- `src/store/useDiagramStore.ts` — single Zustand store: nodes, edges, tool, defaults, undo/redo. **Undo history is module-level (`past`/`future`), snapshot-based, and only pushed by actions that call `pushHistory`** — kept out of the store so it is never serialized; `canUndo`/`canRedo` mirror it for the UI. Discrete edits (`updateNodeData`, `updateEdgeData`) push, but skip no-op patches. A pointer drag pushes once via `beginInteraction()` and then uses a transient action (`updateEdgeDataTransient`, `moveNodesTransient`, `reconnectEdgeEndpoint`). `nudgeSelected` coalesces entries within 500 ms. `loadDiagram` resets history.
- `src/commands/` — the command registry. `commands.ts` is the one list of everything the app can do; `registry.ts` matches a `KeyboardEvent` against it (⌘ and Ctrl are one `meta` flag; `event.code` is the fallback when ⌥ or a non-US layout rewrites `event.key`) and formats a binding per platform. A command's `when` gate is what lets two share a keystroke — and what lets ⌘V fall through to the browser's paste listener when our clipboard is empty, so image paste keeps working. The keyboard handler, the `?` cheat sheet (`ShortcutSheet.tsx`) and the right-click menus (`ContextMenu.tsx`, driven by each command's `contextMenu` tag) are all generated from it: add a shortcut in one place, not four.
- `src/components/Canvas.tsx` — React Flow wrapper. Its keyboard `useEffect` is now three lines: skip typing targets, ask the registry for a command, `preventDefault` and run it. The command context (store, viewport, both clipboards, hold-to-pan, the sheet) is built there with `useMemo`; the copy/paste and copy-style clipboards are refs, since neither belongs in a saved diagram. The right mouse button opens the context menu, so `panOnDrag` is the middle button only.
- `src/lib/arrange.ts` — pure geometry for align / distribute / match size, over plain `{id,x,y,w,h}` rects. The store's `alignSelected` / `distributeSelected` / `matchSizeSelected` map the selection onto it and commit the result through one shared path that skips locked nodes (they still count towards the geometry, so a locked node is the anchor) and pushes **no** history entry when nothing would move. Distribute equalises gaps between *edges*, and match size uses the largest node as its reference — selection order is not tracked anywhere. Both are bound in the registry (⌥⇧ + arrow / H / V to align, ⌘⌥⇧H / ⌘⌥⇧V to distribute) and gated on a real multi-selection.
- Text formatting lives in one presentational `src/components/TextFormatControls.tsx` (value + onChange), rendered both by `TextFormatBar` (one label being edited; translates patches onto a connector's `label*` keys) and by `FloatingToolbar` (the whole selection, via `updateSelectedNodesData`, which skips `shape: 'image'` nodes). Its `target` prop is what tells a shape's label from a connector's: a connector's carries size, bold and italic only, and its size is still one of the three names rather than a number of px.
- `src/nodes/ShapeNode.tsx` — one component renders all 15 drawable shape kinds. The nine **clip shapes** (diamond, triangle, hexagon, parallelogram, document, cloud, star, callout, arrow) are a single filled `<path>` taken from `src/lib/shapePaths.ts` — every outline is drawn in a `viewBox="0 0 100 100"` and stretched to the node's box with `preserveAspectRatio="none"` + `vectorEffect="non-scaling-stroke"`, so a path there is a proportional description and never a pixel one; adding a kind means adding a path, not a branch. Cylinder keeps its own multi-part SVG (its ellipse cap does not stretch like the rest); everything else is a CSS box. `isClipShape` is what tells the two apart. Icons and labels for every kind live in one table, `src/lib/shapeIcons.tsx`, read by the left rail and by the floating toolbar's shape swapper (`setSelectedShapeKind`), so a shape cannot wear two faces. Text editing is a `contentEditable` div committed on blur. **A label's box is not the node's box:** `textInset(kind)` (`shapePaths.ts`) says how far in from each edge a silhouette's text has to sit — as proportions of the node, resolved against its real size in ShapeNode, because a percentage padding in CSS resolves against the *width* on all four sides. `fontSize` is a number of px read through `resolveFontSize` (`src/lib/text.ts`), which also still answers for the `'small'|'medium'|'large'` older diagrams hold — that is why the scale needed no migration. `textColor` overrides the fill's auto-contrast, and `opacity`/`shadow` go on the wrapper (a silhouette casts its shadow with a `drop-shadow` filter, having no box to trace) while `cornerRadius` goes on the box, for the two kinds `canRoundCorners` allows.
- **Floating arrows are a hack:** an edge whose source and target are both 1×1 nodes with `fill: 'transparent', stroke: 'transparent'`. `isAnchor` checks in ShapeNode/Canvas detect these. Don't "fix" transparent fills without checking this.
- `src/edges/ConnectorEdge.tsx` renders a connector; `src/lib/connectorPath.ts` decides its shape. **`buildConnectorPath(kind, …)` is the one place the three kinds are drawn** — straight, elbow, curved — returning the `d`, the point the bend handle sits on, and a polyline the label is interpolated along. It is pure: the edge component feeds it the anchors, the edge's `waypoints`, and — for an elbow only — the corners from `src/lib/manhattanRouter.ts` (extracted from JointJS, MPL-2.0), which is where those waypoints are threaded as `vertices`. A straight connector is a polyline through them and a curve a Catmull-Rom spline (`catmullRomToBezier`), so a bend lies *on* the path for all three kinds. `cleanPath` absorbs sub-8px kinks from grid snapping. The path also reports its `segments` — one grab handle per run, in path order: dragging one inserts a bend at that index (`insertEdgeWaypoint`) and keeps dragging it (`setEdgeWaypointTransient`), double-clicking a bend removes it (`removeEdgeWaypoint`), and an elbow's drag is held across the run it grabbed. There is no handle at the centre any more — the add-label button sits there and swallows its pointer events, which is also why a handle that would land under the label slides along the path until it is clear.
- Arrowheads are top-level edge fields (`markerStart`/`markerEnd`), regenerated from `data` by `computeMarkers` (`src/lib/edgeMarkers.ts`, re-exported from the store). Persisted JSON stores both. `updateEdgeData` / `updateSelectedEdgesStyle` regenerate them whenever a patch touches `stroke`, `strokeWidth`, `startArrowStyle` or `endArrowStyle`.
- **Each end wears one of five `ArrowStyle`s** (`none` / `arrow` / `open` / `circle` / `diamond`) and React Flow builds defs for only two of them, so `computeMarkers` returns the *id* of a `<marker>` this app defines — React Flow passes a string marker through as `url(#…)` untouched. `src/edges/ConnectorMarkerDefs.tsx` renders one def per distinct style/colour/size across the current edges (`markerDefsForEdges`), through `ViewportPortal`: image export captures `.react-flow__viewport`, so defs mounted outside it would vanish from every exported file. Marker size steps with `strokeWidth` (8/10/14px) rather than scaling with it — `markerUnits="userSpaceOnUse"`.
- Diagram format is **v2**. v1 carried `startArrow`/`endArrow` booleans; the `v1ToV2` step rewrites them as styles, drops them, and recomputes every edge's markers — which is also what repoints old rows at this build's defs, so `v0ToV1` no longer touches markers at all.
- `server/` — Express 5. `router.ts` is the diagram CRUD; `auth.ts` is BetterAuth with Prisma adapter; `middleware.ts` puts `req.user`/`req.session` on the request, typed in `types.ts` by declaration-merging `Express.Request` with `auth.$Infer.Session` — routes read it through `authedUser(req)`, never a cast. `validation.ts` holds the zod body schemas (POST/PUT `/api/diagrams`, POST members, POST versions); `rateLimit.ts` the limiter factories (600/15 min on `/api`, 60/15 min on `POST /api/images`, 300/15 min on `/api/shared/*`, all skipped when `NODE_ENV=test`). `GET /api/health` is DB-free; `?deep=1` also pings Postgres and 503s if it is down.
- **`server/access.ts` is the one place that decides who may do what with a diagram.** A route never writes `where: { id, userId }` any more: `requireDiagramRole(req, res, minRole, select)` answers `404` when the caller has no access at all (a diagram they cannot see stays indistinguishable from one that is not there), `403` when they can see it but not do *this* to it, and otherwise hands back the columns it was asked for — the access check and the row come out of **one** query, the caller's member row read as a filtered relation. Roles are totally ordered (`owner > editor > viewer`). GET needs viewer+, PUT editor+, version *reads* viewer+, version snapshot/restore editor+, and DELETE / duplicate / star / sharing / member management are owner-only; `starred` is refused on an editor's PUT because it is one column on the row, not a per-user flag. `server/sharing.ts` holds both halves of sharing: `sharingRouter` (mounted inside `apiRouter`, so behind `requireAuth`) for `POST`/`DELETE /api/diagrams/:id/share` and the member routes, and `sharedRouter` (mounted by `index.ts` at `/api/shared`, **no session at all**) for `GET /api/shared/:token` and `/:token/images/:imageId` — the token is the whole credential, and the diagram's own JSON is the allow-list for which images it can reach. `GET /api/images/:id` now also serves a non-owner who is a member of some diagram that draws it, which costs one scan of the diagrams shared *with* that user (documented at `memberCanSeeImage`).
- **`server/versions.ts` is version history**, mounted inside `apiRouter` (there is no unauthenticated half: a share token buys a look at the diagram as it is, not at every state it has ever been in). `PUT /api/diagrams/:id` calls `recordVersionIfDue` whenever the edit changes `data` — it snapshots the **previous** `data`+`title`, and only when the newest existing snapshot has aged past `VERSION_INTERVAL_MS` (default 10 min), so an afternoon of 2 s autosaves leaves one row per burst of editing rather than one per keystroke; a rename/star/thumbnail PUT records nothing and does not even read the old JSON back. Retention keeps the newest `MAX_VERSIONS` (default 50) per diagram, deleting the surplus **by id** (a timestamp cutoff would have to guess about rows sharing a millisecond). Both the snapshot and the prune are best-effort — logged, never a failed PUT. The routes are `GET …/versions` (metadata only, newest first), `GET …/versions/:versionId` (with `data`, for preview; the lookup is scoped by `diagramId`, so another diagram's version is a 404), `POST …/versions` (manual snapshot of the *current* data, ignoring the interval), and `POST …/versions/:versionId/restore`, which writes a `Before restore` snapshot **first** — not best-effort, that one — then overwrites `data`/`title` and answers with `{ id, title, data, updatedAt }` so the client's conflict guard can advance. **Known gap:** `deleteOrphanImages` scans diagrams only, so an image edited off the live board is deleted even while a stored version still draws it.
- `prisma/schema.prisma` — BetterAuth tables + `Diagram { data: Json, thumbnail (never written), starred, shareToken? @unique }` + `DiagramMember { diagramId, userId, role }` (`@@unique([diagramId, userId])`; the owner is `Diagram.userId` and never a member row) + `DiagramVersion { diagramId, data: Json, title, label?, createdById? }` (`@@index([diagramId, createdAt(sort: Desc)])`; cascades from the diagram, `SetNull` from the author, whose account may go while someone else's diagram lives on). The schema is applied with **`prisma migrate deploy`** from `prisma/migrations/` (`npm run db:migrate:deploy`; `deploy/deploy.sh` and CI's e2e job run it). Change it with `npm run db:migrate -- --name x` and commit the generated directory; `npm run db:push` is only for a throwaway local DB. Any database created *before* migrations existed (i.e. with `db push`) must be baselined once, or `migrate deploy` tries to re-create every table: `npx prisma migrate resolve --applied 20260906065812_init` — see DEPLOYMENT.md § Database migrations.
- Persistence: `CanvasPage.tsx` subscribes to the store and autosaves with a 2 s debounce through `src/lib/autosave.ts`; unmount flushes a pending save and `pagehide` fires a keepalive save. **A failed save retries itself** — 1 s, 2 s, 4 s … capped at 30 s, unlimited while the page is open — and stays `isPending()` until one is confirmed; a new edit during a backoff falls back to the normal debounce. The autosaver's state drives `saveStatus` (`retrying` → amber in the TopBar) via `onStateChange`; `saveDiagram` never rejects (it reports through `saveStatus`), so CanvasPage translates that back into the rejection the autosaver retries on. Saved JSON is versioned — `serializeDiagram` stamps `version: CURRENT_DIAGRAM_VERSION`, and `loadDiagram` runs everything through `migrateDiagramData` (`src/lib/diagramMigrations.ts`), which upgrades unversioned v0 rows and throws on a payload from a newer build (CanvasPage shows that instead of loading, leaving autosave unarmed). Changing the shape of a diagram means a new migration step, not a silent read of the old one. **Every save is guarded**: the client keeps the `updatedAt` it loaded (then whatever each save returns, monotonically, through `noteSaved` — thumbnails write through the same `PUT` and bump it too) and sends it as `ifUnmodifiedSince`; the server compares it to the row as timestamps and answers `409 { error, updatedAt }` without writing when a second tab got there first. A 409 and a 401 are both *terminal* — `saveDiagram` returns them as outcomes rather than throwing, CanvasPage cancels the autosaver and stops scheduling, and the user is offered the TopBar's conflict banner (Reload / Overwrite, the latter resending with no guard) or `ReauthDialog`. A 401 no longer navigates from the canvas at all: `api.request` rejects with `UnauthorizedError` and `setUnauthorizedHandler` decides what else happens — the redirect to `/login` is still the default everywhere else.
- View preferences (minimap, grid snapping) are per-browser, not per-diagram: `src/store/useViewPreferences.ts` holds them and writes each change through `src/lib/preferences.ts`, a deliberately forgiving `localStorage` wrapper (blocked storage, a full quota and a value of the wrong type all fall back to the caller's default). Nothing here reaches `DiagramData`, a save or the undo history.
- Images: `server/images.ts` (`/api/images`, raw `image/*` up to 10 MB) writes bytes to `UPLOAD_DIR/<userId>/<id>.<ext>` and rows the metadata in `Image`; `server/imageTypes.ts` sniffs magic bytes (never the Content-Type); `server/imageRefs.ts` garbage-collects: deleting a diagram, **and any `PUT /api/diagrams/:id` that drops an image from `data`**, deletes the images no other diagram still references (the scan runs after the row is written, or the pre-edit JSON would count as a live reference). JSON body limit is 5 MB, which is why a diagram stores the `/api/images/<id>` URL and never the bytes. Client side: paste, drop and the rail's picker all go through `src/lib/useImageInsert.ts` → `src/lib/imageUpload.ts` (downscale to 2000 px, upload, then swap the URL into the "Uploading…" placeholder node). Nodes of `shape: 'image'` render as the bare `<img>`; **rectangles carrying a base64 `data.imageSrc` are the pre-upload format and must keep rendering** — old diagrams still hold them, and `src/lib/imageBackfill.ts` quietly moves them out: CanvasPage runs it after the load (never blocking it), each inline image is uploaded, and `applyImageBackfill` repoints the node with **no** history entry, leaving the normal autosave to persist it. A failed upload leaves that node inline for the next open.

## Conventions

- Every store action that mutates nodes/edges must `pushHistory` first.
- `src/lib/defaults.ts` owns the default edge style: `DEFAULT_EDGE_STROKE`, `DEFAULT_STROKE_WIDTH` / `CONNECTOR_STROKE_PX`, `DEFAULT_START_ARROW` / `DEFAULT_END_ARROW`, and `makeEdgeData(connectorType)`. Build a new connector's `data` with the factory; never re-inline the hex (it is spelled out in exactly one place). The optional fields (`strokeWidth`, both arrow styles) are absent on older diagrams, so read them through those defaults — that is what keeps an old connector drawn exactly as it was.
- Tests: pure logic next to the file (`*.test.ts`), store tests drive `getState()`, API tests mock `./db.js` and `./middleware.js` with `vi.mock`, user flows in `e2e/`. Bug fixes start with a failing test; `it.fails` marks a documented known bug.
- Don't loosen a test to make it pass. If a router/geometry assertion fails, the tolerance is documented in the test — investigate before changing it.
